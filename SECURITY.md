# Security model

This repository publishes **memory from a penetration-testing machine**. That is
unusual, and it is the whole reason the tooling in `tools/` exists. Read this before
cloning it into anything public.

## What is in the seed

`seed/hindsight-bank.zip` is a portable bank export: documents, extracted facts,
observations, mental models and knowledge pages. It is **not** a database dump and
it contains **no embeddings** (they are recomputed on import), which is why a
553 MB bank fits in 8.9 MB.

The documents it carries are the maintainer's own working memory: walkthroughs,
notes, command transcripts, decisions. They are sanitized for *secrets*, not for
*content*.

## What the gate guarantees

`tools/verify-seed.sh` refuses to let a commit happen if any of these appear in the
seed or the sources:

* captured flags (`HTB{...}`, `CTF{...}`, `flag{...}` with a real-looking body);
* private keys, in whole blocks or as headers;
* cloud and provider tokens (AWS, GitHub, OpenAI, Anthropic, Slack, Google, JWTs);
* credentials embedded in URLs;
* `password:`/`token:`/`api_key:`-style assignments whose value looks like a real
  secret rather than a placeholder.

`tools/sanitize_export.py` rewrites those literals to `[REDACTED-<class>]` in the
exported copy (never in the live bank) and records what it removed in
`seed/REDACTION-REPORT.md`. Every redaction is visible in the published text: the
aim is that a reader can tell something was taken out, and what class of thing it
was, without ever seeing it.

## What the gate does **not** guarantee

Being explicit about this matters more than the list above.

* **It cannot find an unknown class of secret.** It finds the classes it knows. A
  novel token format, a password written as prose, or a secret with no keyword
  nearby will pass.
* **It does not treat IP addresses, e-mail addresses or paths as secrets.** They are
  reported as warnings (with a count), left in place, and published. The seed
  contains lab addresses, hostnames and e-mail addresses from the documents; that is
  a deliberate decision, not an oversight. `--strict-warn` raises the line for
  anyone who disagrees.
* **Home directories of the operator's own machines are normalised** to
  `[REDACTED-home]` when the seed is generated, because they identify the source
  machine. Home directories that appear *inside target documents* are knowledge and
  stay.
* **Flags are not the only sensitive thing in a pentest memory.** Machine names,
  credentials policy, network topology and the shape of an engagement are all in
  there. Publishing means publishing those too.

## Why the gate exists

An earlier working repository of the maintainer's was published with a directory of
collected write-ups inside it: a few hundred files, dozens of which contained
literal flags captured during authorized work. Once that history is public, editing
the file does not unpublish it.

This repository exists partly so that the same mistake is not repeatable: there is
no collected-write-ups directory, the ignore rules in `.gitignore` say why, the seed
is generated by a pipeline rather than by hand, and a sanitizing gate runs before
anything reaches `seed/`.

The decision of what to do about the earlier repository's history is the operator's,
and is tracked in `docs/decisions.md`.

## Reporting

If you find material in this repository that should not be public, open an issue
with the file and the class of material only — **do not paste the value**. The
maintainer will redact at the source and regenerate the seed, which rewrites the
artifact and its manifest hash in a single commit.
